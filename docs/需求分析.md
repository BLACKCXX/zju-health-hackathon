# 需求分析

## 1. 赛题理解

本项目面向"AI 全栈极速黑客松·学科知识整合智能体开发"赛题，目标是构建一个面向 7 本医学教材的学科知识整合智能体。

**核心问题：** 多本医学教材之间存在内容重复、表述差异、逻辑组织不一致的情况。这导致：
- 学生重复阅读相似内容，效率低下
- 教师难以全面评估不同教材对同一知识点的覆盖与交叉
- 缺乏系统性的跨教材知识整合工具

**解决方案：** 构建一套整合系统，提供教材管理、RAG 问答、知识图谱、跨教材整合分析、教师反馈修正、Markdown 报告导出等功能。

## 2. 用户与使用场景

### 2.1 学生用户
- 输入医学问题，获得带教材引用来源的结构化回答
- 查看知识闪卡，辅助记忆与复习
- 从闪卡跳转进入知识图谱工作台，可视化理解知识点关系
- 在图谱中点击节点查看详情和证据来源

### 2.2 教师用户
- 上传并管理教材，查看解析状态和章节结构
- 选择单本教材生成知识图谱，查看该教材内部知识结构
- 选择主题生成跨教材整合图谱，查看重复/互补/缺失分析
- 对图谱节点或边提交反馈（keep/delete/split/merge/edit），系统基于反馈更新图谱
- 导出 Markdown 整合报告用于教学材料整理

### 2.3 教学管理者
- 查看系统状态（教材数量、索引状态、chunk 数量）
- 查看压缩比，评估整合效率
- 查看整合报告，了解教材覆盖情况

## 3. 核心功能需求

### 3.1 教材管理与多格式解析

| 功能 | 说明 |
|------|------|
| 教材上传 | 支持 PDF、Markdown、TXT 格式，上传至 `uploads/textbooks/` |
| 多格式解析 | Parser Agent 将不同格式统一解析为 Textbook Schema，保留教材名、章节、页码 |
| 文件列表展示 | 显示文件名、格式、页数、字符数、解析状态、章节数量 |
| 章节结构展示 | 展示解析后的章节树结构 |
| RAG 索引构建 | 解析后自动将教材内容分块、embedding，建立 FAISS 或 TF-IDF 索引 |

### 3.2 标准 RAG 问答

| 功能 | 说明 |
|------|------|
| 自然语言查询 | 用户输入医学问题 |
| Router Agent | 提取关键词、展开查询、判断意图（医学问题/症状/问候） |
| Retrieval Agent | 基于 chunk + embedding/FAISS/TF-IDF 检索 top-k 证据 |
| 带引用回答 | Answer Agent 基于证据生成回答，强制标注教材名、章节、页码、原文引用 |
| 拒答机制 | 无可靠证据时明确告知"教材片段中未找到足够依据" |

### 3.3 知识小回答与闪卡

| 功能 | 说明 |
|------|------|
| 知识小回答 | 简洁回答 + 教材依据 + 详细解释 + 引用来源 + 医学安全提示 |
| 右侧知识闪卡 | 基于问题关键词和检索证据自动生成，包含 title、definition、key_points、related_terms |
| 闪卡跳转图谱 | 点击闪卡上的"查看图谱"按钮，将主题传入知识图谱工作台 |

### 3.4 单本教材知识图谱

| 功能 | 说明 |
|------|------|
| 教材选择 | 选择一本教材及其章节 |
| 证据检索 | 从该教材的 RAG 索引中检索相关证据 |
| Graph Agent | 基于证据生成 GraphJSON，包含节点、边、关系类型、evidence_ids |
| 图谱交互 | ECharts 支持节点点击、拖拽、缩放 |
| 节点详情 | 点击节点查看定义、详细信息、来源教材、重复/互补分析 |
| 教师反馈 | 对节点或边提交反馈（keep/delete/split/merge/edit） |
| 报告导出 | 导出该教材图谱的 Markdown 报告 |

### 3.5 跨教材整合图谱

| 功能 | 说明 |
|------|------|
| 主题输入 | 输入主题或选择知识点 |
| 多书证据检索 | 跨多本教材检索 evidence |
| 节点对齐 | 按名称、定义、embedding 相似度对齐不同教材中的相同节点 |
| 整合决策 | 对每个节点做出 merge/keep/remove 决策 |
| 重复分析 | 标注哪些知识点在多本教材中均出现（重叠） |
| 互补分析 | 标注哪些知识点在不同教材中各有不同侧面的补充 |
| 缺失分析 | 标注哪些核心节点在某教材中缺失证据 |
| 压缩比 | 计算 `integrated_chars / original_chars`，目标不超过 30% |
| 教师反馈 | 可修正误合并的节点，恢复误删的节点 |
| Markdown 报告导出 | 导出包含节点说明、整合决策、压缩比、引用的完整报告 |

### 3.6 教师反馈与图谱更新

| 功能 | 说明 |
|------|------|
| 反馈类型 | keep / delete / split / merge / edit |
| 反馈对象 | 节点（node）或边（edge） |
| 图谱补丁 | feedback_service 计算 graph patch，更新节点状态 |
| 反馈记录 | 每个反馈生成带时间戳的 FeedbackRecord，写入 graph |
| 上下文保留 | 同一会话中教师反馈持续生效 |

### 3.7 Markdown 报告导出

| 功能 | 说明 |
|------|------|
| 内容结构 | 核心概念概述、图谱摘要、节点说明、重复/互补/缺失分析、教师反馈记录、压缩比、引用来源 |
| 格式 | Markdown，可直接用于教学材料 |
| 文件名 | `{topic}_跨教材整合报告.md` |

## 4. 知识点粒度定义

本系统中，以下实体算作一个独立的知识点：

- **概念（concept）**：核心医学概念的定义，如"炎症"、"发热"
- **定义（definition）**：对某个概念的完整解释
- **机制（mechanism）**：病理生理机制，如"休克的微循环机制"
- **疾病（disease）**：具体疾病名称
- **症状（symptom）**：临床表现，如"胸痛"、"呼吸困难"
- **诊断方法（diagnosis）**：诊断依据、检查指标
- **治疗方法（treatment）**：治疗手段、用药方案
- **危险因素（risk_factor）**：病因、危险因素
- **并发症（complication）**：疾病并发症
- **预防措施（prevention）**：预防与控制措施

知识点之间通过边关系连接：`causes`、`belongs_to`、`associated_with`、`diagnosed_by`、`treated_by`、`complicates`、`prevents`、`explains`、`contrasts_with`。

## 5. 重复判定标准

判断两个知识点重复的标准：

| 维度 | 说明 |
|------|------|
| 名称相似 | 关键词相同或近似（如"肝炎"与"病毒性肝炎"） |
| 定义一致 | embedding 余弦相似度高，或 LLM 判断定义实质相同 |
| evidence 上下文相似 | 来自不同教材但讨论的是同一主题 |
| 人工教师反馈纠正 | 教师可指出误合并的节点，系统执行 split 操作恢复 |

具体实现上：
- Retrieval Agent 在检索时按 book 分组，每本教材取 top-k evidence
- Graph Agent 的 `_extract_concepts` 按文本分类提取概念，同一类别的 concept 自动聚拢
- Integration Agent 做名称 + embedding 双重对齐，confidence 低于阈值时保留 keep 决策而不 merge

## 6. 互补与缺失判定

### 6.1 互补判定

当多个教材对同一主题各有不同侧面的描述时，判定为互补：
- 教材 A 描述定义和机制
- 教材 B 描述临床表现和诊断
- 教材 C 描述治疗方案和并发症

判定依据：`GraphEvidence.book_sources` 包含多本教材，且节点 `type` 不同（如 mechanism + diagnosis + treatment）。

### 6.2 缺失判定

当某个核心节点在某本教材中没有 evidence 支持时，判定为缺失：
- 主题节点有 evidence，但子节点（如"并发症"）在某教材中缺失
- Integration Agent 的 `missing_summary` 字段标注"未检索到证据的分支已标注为证据不足"

判定依据：`compare_sources_for_node` 返回 `complement_analysis` 中单书 evidence 不足的情况。

## 7. 教学连贯性保障

压缩操作不得破坏学习路径，系统通过以下机制保障连贯性：

| 保障措施 | 说明 |
|------|------|
| 保留 prerequisite 关系 | 边关系 `belongs_to`、`causes` 保留核心定义节点 |
| 保留核心定义和机制 | definition / mechanism 类型的节点优先级最高，不会优先删除 |
| 保留诊断/治疗链路 | diagnosed_by / treated_by 类型的边保留 |
| 教师反馈可恢复误删 | delete 操作仅标记 `status: deleted`，不物理删除节点 |
| 反馈记录可追溯 | 每个操作生成 FeedbackRecord，包含 before/after 快照 |

## 8. 压缩比计算方式

```
original_chars = sum(len(evidence[i].quote) for i in relevant_evidence)
integrated_chars = sum(len(node.summary) for node in graph.nodes)
compression_ratio = integrated_chars / original_chars
```

目标：compression_ratio ≤ 0.30（即压缩后字符数不超过原始的 30%）。

压缩后的内容包含：节点 summary（定义/机制/临床表现/诊断/治疗/并发症/预防）+ 图谱报告文本。每个节点保留完整的学习路径关系。

## 9. RAG 分块策略选择依据

| 参数 | 值 | 依据 |
|------|-----|------|
| chunk_size | 700 字符 | 医学教材段落较长，完整定义+解释通常在 500-700 字；700 字可容纳一个独立的知识点段落 |
| overlap | 80 字符 | 防止知识点被块边界截断；80 字约覆盖 10% 的 chunk，保证上下文连续性 |
| top_k | 5（默认），可配 1-30 | 保证回答有足够证据又不引入过多噪声；图谱场景用 global_top_k=30 |

metadata 保留：textbook_id、chunk_id、page、chapter、book_name，确保引用可溯源。

## 12. 新增提分需求说明

### 12.1 为什么需要整合前后对比

跨教材整合不是简单把 evidence 堆叠到页面上，而是要证明系统完成了“压缩、去重、保留差异、形成结构”的过程。评审需要直观看到：

- 整合前有多少原始 evidence、多少教材和章节来源
- 整合后压缩为多少节点、边和摘要字数
- merge / keep / remove 决策是否真的发生
- 压缩比是否接近赛题要求的 30% 控制目标

因此需要 `IntegrationComparePanel` 将“原始 evidence 集合”和“整合后 GraphJSON”并排展示，避免跨教材整合能力只停留在后端字段中。

### 12.2 为什么教师反馈需要触发重新检索 evidence

教师反馈往往不是单纯的 UI 标注，而是对知识覆盖范围的修正。例如“缺少炎症介质证据”“补充急性炎症机制”等评论，意味着当前节点 evidence 不完整。如果只记录 feedback_record，图谱不会变得更可信。

轻量闭环的必要性：

- 教师指出“缺少 / 补充 / 完善”时，系统应主动检索新 evidence
- 新 evidence 追加到 `graph.evidence`，保证后续报告和右侧证据面板可追溯
- 新 `evidence_id` 绑定到目标节点，避免把全局 evidence 错展示给无关节点
- `node.summary` 标记“已根据教师反馈补充相关教材证据”，让多轮修订结果可见
- `feedback_record` 记录 `retrieval_triggered` 和 `added_evidence_count`，便于审计和演示

该闭环不重建全量索引，不改变 RAG 核心策略，只在现有索引上做 top-3 轻量检索，风险低且能体现多轮 Agent 工作流。
